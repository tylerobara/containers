What every image ships with

The same pipeline for every image family — one workflow each, so a change to one can never rebuild another.

Built from upstream source

melange compiles the release tarball with upstream's own build flags into a signed APK.

Declarative assembly

apko builds the image from a package list on Wolfi — no Dockerfile, no RUN steps, lockfile-guarded.

grype scan every build

The full report for each published digest is published here and in raw JSON.

Cosign keyless signature

Signed only when the scan has zero Low+ findings, with the building workflow as the certificate identity.

Smoke tested

Every build runs the image's own test.sh against the published image before it is scanned or signed.

Multi-arch, native runners

amd64 and arm64 legs build natively and are joined into one manifest index.

Common questions

Short answers to what people ask before swapping an image.

Why is there no Dockerfile?

Every binary is compiled from the upstream release tarball by melange into a signed APK, and the image is assembled declaratively by apko from that APK plus Wolfi packages. There is no RUN step, so the image contents are exactly the package list — reproducible, and every file is attributable to a package grype can scan.

Why are some images not signed?

Signing is gated on the scan: an image is cosign-signed only when grype reports zero findings at Low severity or above. An unsigned image is published and usable, but its latest build carried at least one Low+ finding — the Advisories tab on its page shows which.

How often are the images rebuilt?

Daily. Each image family has its own workflow and schedule, so a rebuild picks up fresh Wolfi CVE patches within 24 hours. Upstream version bumps arrive as pull requests from the update-versions workflow and rebuild only the image whose directory changed.

How do I use the PostgreSQL images with CloudNativePG?

Apply the sha-pinned ClusterImageCatalog — kubectl apply -f https://tylerobara.github.io/containers/data/cluster-image-catalog.yaml — and reference it from your Cluster with imageCatalogRef. Each major is pinned to its multi-arch manifest digest, refreshed on every rebuild.

What does "scanned" mean here?

Every published build is scanned with grype after publish, and the full JSON report is published with this site. The counts on each page are raw grype findings for that exact digest — no VEX suppression is applied.
