How images stay current

Two independent loops: a daily rebuild that picks up Wolfi package fixes, and upstream version bumps that arrive as pull requests.

One workflow per image family

Every family — PostgreSQL, the CloudNativePG operator, OpenBao, os-shell, DokuWiki, Grafana Image Renderer, Cilium and cert-manager — has its own workflow. Routing is the nativeon.push.paths filter, so a change to one image's directory rebuilds only that image, and one family's failure can never cancel another's build.

Daily rebuilds

Each workflow runs on its own daily schedule, staggered a few minutes apart from 06:00 UTC. A rebuild re-resolves the apko package set against Wolfi, so a CVE fix that lands in Wolfi reaches a published tag within a day — without a commit. Each rebuild runs the full pipeline:

  1. melange compiles the upstream source on native amd64 and arm64 runners;
  2. apko assembles the image, guarded by a committed lockfile;
  3. the image's own test.sh smoke-tests the published image;
  4. grype scans the published digest;
  5. cosign signs it — only if the scan has zero findings Low or above;
  6. this site redeploys with the fresh entry.

Upstream version bumps

The update-versions workflow checks upstream daily (PGDG for each tracked PostgreSQL major, GitHub releases for everything else) and opens a pull request bumpingversion and sha256 in the melange config. Merging the PR rebuilds, rescans and resigns only that image, and updates its entry here in place.
