Tags & pinning

Every build publishes several tags pointing at the same manifest. Which one you pin decides what happens when the software changes underneath you.

Pin by digest for immutability

A digest is content-addressed — it can never move. Each image page lists the digest that was scanned.

ghcr.io/tylerobara/containers/openbao:2.7.2@sha256:5efd3581cffc304f9330e948b06393e00420b0c2fa4272a30ab153ee4ae19f55

What each tag does

ReferenceExampleBehavior
Digest…@sha256:…Immutable content identity. Never moves.
Version:2.7.2Moves when that upstream version is rebuilt with newer Wolfi packages (daily).
Minor line:2.7Newest patch within that minor line.
Latest:latestNewest build, including across major versions.

PostgreSQL

PostgreSQL publishes no latest: CloudNativePG requires the tag to start with the major version, and a rolling tag across majors would be a data-directory upgrade in disguise. Each major publishes :18, :18.6 and-wolfi-suffixed equivalents. For clusters, prefer the sha-pinnedClusterImageCatalog.

Which should you pin?

Pin a minor line if you want ongoing patches and Wolfi CVE fixes without being moved to a new feature release. An exact version tag still receives daily rebuilds of the same upstream version. Pin a digest when you need a byte-identical artifact and will update it deliberately — Renovate or Dependabot can keep digest pins fresh.
