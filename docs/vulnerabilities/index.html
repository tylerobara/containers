Scans & signing

Every count on this site is a raw grype finding against the exact digest that was published.

What is scanned

After publish, each image's multi-arch manifest is scanned with the latestgrype. The full JSON report is kept with the build entry in data/index.json — the Advisories tab on each image page is rendered from it. No VEX statements or ignore rules are applied.

The signing gate

An image is cosign-signed only when its scan reports zero findings at Low severity or above. Negligible and Unknown findings do not block signing. Currently 35 of 42 images carry a signature on their latest build.

An unsigned image is still published and usable — the gate exists so that a signature means something specific: this digest scanned clean when it was built. Usecosign verify in admission control (Kyverno, policy-controller) to only admit images that passed it.

Reading the counts

  • Fixable means grype knows a fixed version. Most fixable findings disappear on the next daily rebuild once Wolfi ships the fix.
  • Not fixed / won't fix findings usually sit in a bundled runtime (e.g. Chromium in the Grafana renderer) and clear when that package moves upstream.
  • A clean scan means no findings in one database snapshot — not proof the image is free of vulnerabilities.
